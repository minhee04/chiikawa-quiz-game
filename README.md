# 🐰 치이카와 퀴즈 게임

## 1. 프로젝트 개요

치이카와 캐릭터를 주제로 한 Python 기반 터미널 퀴즈 게임입니다.

사용자는 퀴즈를 직접 추가하거나 삭제할 수 있으며, 등록된 퀴즈를 풀고 자신의 점수와 기록을 확인할 수 있습니다. 퀴즈 데이터와 점수 기록은 JSON 파일에 저장되어 프로그램을 종료한 후에도 유지됩니다.

## 2. 주제 선정 이유

요즘 빠져있는 귀여운 캐릭터들을 활용해 간단하면서 재밌는 퀴즈 게임을 만들고 싶었습니다.

평소 관심 있는 캐릭터를 주제로 선정하여 직접 퀴즈를 만들고 풀어보는 과정을 통해 Python 프로그래밍과 데이터 저장 및 관리 방법을 익히고자 했습니다.

## 4. 주요 기능

### 퀴즈 게임
- 등록된 퀴즈를 무작위 순서로 출제
- 사용자가 원하는 문제 수 선택
- 정답 여부에 따른 점수 계산
- 힌트 기능 제공
- 힌트를 사용한 문제는 정답을 맞혀도 점수 미부여

### 퀴즈 관리
- 새로운 퀴즈 추가
- 등록된 퀴즈 목록 확인
- 퀴즈 삭제 전 확인 기능
- 중복 퀴즈 등록 방지
- 입력값 검증 기능
- 키워드를 이용한 퀴즈 검색
- 검색 결과에서 퀴즈 상세 정보 확인

### 점수 관리
- 최고 점수 확인
- 게임별 점수 기록 확인
- 게임 날짜, 전체 문제 수, 정답 수 저장
- 전체 퀴즈 수, 게임 횟수 및 정답률 통계 확인

## 6. 프로젝트 구조

```text
chiikawa-quiz-game/
│
├── main.py          # 퀴즈 게임 프로그램
├── state.json       # 퀴즈 및 점수 데이터 저장 파일
├── state.json.bak   # 이전 데이터 백업 파일
├── README.md        # 프로젝트 설명 및 실행 방법
└── .gitignore       # Git 추적 제외 파일 설정
```

`state.json.tmp`는 데이터를 저장하는 과정에서 생성되는 임시 파일이며, 저장이 완료되면 자동으로 실제 데이터 파일로 교체됩니다.

`state.json.bak`과 `state.json.tmp`는 `.gitignore`에 등록하여 Git 추적 대상에서 제외합니다.

## 7. 프로그램 구조

본 프로그램은 `Quiz`와 `QuizGame` 두 개의 클래스로 구성되어 있으며, 각각 퀴즈 데이터와 게임 진행을 담당합니다.

### Quiz 클래스

개별 퀴즈 데이터를 관리하는 클래스입니다.

- 퀴즈 ID 관리
- 질문과 선택지 저장
- 정답 및 힌트 저장
- 사용자의 답변이 정답인지 확인

### QuizGame 클래스

전체 퀴즈 게임의 진행과 데이터를 관리하는 클래스입니다.

- JSON 파일에서 퀴즈 데이터 불러오기
- 퀴즈 데이터 저장하기
- 퀴즈 추가 및 삭제
- 퀴즈 목록 출력
- 퀴즈 무작위 출제 및 게임 진행
- 점수 계산 및 최고 점수 관리
- 점수 기록 저장 및 출력
- 퀴즈 검색 및 상세 정보 확인
- 게임 통계 출력
- 메뉴 출력 및 사용자 입력 처리

### 객체지향 프로그래밍을 선택한 이유

퀴즈 데이터와 게임 진행 기능을 구분하여 관리하기 위해 객체지향 프로그래밍 방식을 사용했습니다.

`Quiz` 클래스는 개별 퀴즈의 데이터와 정답 확인 기능을 담당하고, `QuizGame` 클래스는 여러 퀴즈를 관리하고 게임을 진행하는 역할을 담당합니다.

함수만 사용하는 방식보다 관련 데이터와 기능을 하나의 클래스로 묶어 관리할 수 있으며, 기능이 추가되거나 수정될 때 코드의 역할을 구분하기 쉽다는 장점이 있습니다.

## 8. 데이터 파일 설명

프로그램의 데이터는 프로젝트 최상위 폴더에 위치한 `state.json` 파일에 저장됩니다.

### 파일 경로

```text
chiikawa-quiz-game/state.json
```

### 파일 역할

프로그램에서 사용하는 퀴즈 정보와 게임 점수 기록을 JSON 형식으로 저장합니다.

프로그램을 종료한 후 다시 실행해도 기존 데이터가 유지됩니다.

### 필드 구조

| 필드명 | 설명 |
|---|---|
| `quizzes` | 등록된 퀴즈 목록 |
| `score_history` | 게임별 점수 기록 |
| `high_score` | 지금까지 달성한 최고 점수 |

**quizzes 필드**

각 퀴즈는 다음 정보를 저장합니다.

| 필드명 | 설명 |
|---|---|
| `id` | 퀴즈 고유 번호 |
| `question` | 퀴즈 질문 |
| `choices` | 객관식 선택지 |
| `answer` | 정답 선택지의 인덱스 |
| `hint` | 퀴즈 힌트 |

**score_history 필드**

각 게임의 결과를 기록합니다.

| 필드명 | 설명 |
|---|---|
| `date` | 게임 진행 날짜 및 시간 |
| `total` | 전체 문제 수 |
| `correct` | 정답 수 |
| `score` | 획득 점수 |

### JSON 데이터 예시

```json
{
    "quizzes": [
        {
            "id": 1,
            "question": "치이카와의 친구 중 파란색을 띠는 캐릭터는?",
            "choices": [
                "하치와레",
                "우사기",
                "모몽가",
                "쿠리만쥬"
            ],
            "answer": 0,
            "hint": "말을 잘하고 기타를 연주하는 캐릭터야."
        }
    ],
    "score_history": [
        {
            "date": "2026-11-01 15:30:00",
            "total": 5,
            "correct": 4,
            "score": 4
        }
    ],
    "high_score": 4
}
```

### JSON을 선택한 이유

JSON은 사람이 읽고 이해하기 쉬운 데이터 형식이며, Python의 `json` 모듈을 이용하면 별도의 외부 라이브러리 없이 데이터를 저장하고 불러올 수 있습니다.

퀴즈와 점수 기록처럼 구조가 명확하고 데이터 규모가 크지 않은 프로젝트에 적합하다고 판단했습니다.

**장점**
- 사람이 읽고 수정하기 쉬움
- Python의 기본 `json` 모듈로 처리 가능
- 별도의 데이터베이스 설치가 필요하지 않음
- 리스트와 딕셔너리를 활용해 계층적인 데이터 구조 표현 가능

**단점**
- 데이터가 많아지면 파일 전체를 읽고 쓰는 과정에서 성능이 저하될 수 있음
- 여러 사용자가 동시에 데이터를 수정하는 환경에 적합하지 않음
- 관계형 데이터베이스처럼 데이터 간 관계와 무결성을 체계적으로 관리하기 어려움

따라서 현재 프로젝트에는 JSON을 사용하고, 데이터 규모가 커지거나 여러 사용자가 동시에 접근해야 하는 서비스로 확장된다면 SQLite 또는 MySQL과 같은 데이터베이스를 사용하는 것이 적합하다고 생각했습니다.

### 데이터 구조를 설계한 이유

퀴즈 목록은 여러 개의 퀴즈 데이터를 관리해야 하므로 리스트로 구성하고, 각 퀴즈의 질문, 선택지, 정답, 힌트는 딕셔너리로 저장했습니다.

게임 기록 역시 여러 번의 플레이 결과를 저장해야 하므로 리스트로 구성하고, 각 기록은 딕셔너리로 관리했습니다.

이러한 구조를 사용하면 새로운 퀴즈와 점수 기록을 추가하거나 특정 데이터를 검색하고 수정하기 쉽습니다.

## 9. 데이터 저장 및 백업

데이터 저장 과정에서 발생할 수 있는 문제에 대비하기 위해 임시 파일과 백업 파일을 사용합니다.

### 저장 과정

1. 데이터를 `state.json.tmp` 임시 파일에 저장합니다.
2. 기존 `state.json` 파일이 존재하면 `state.json.bak` 파일로 백업합니다.
3. 임시 파일 저장이 완료되면 `os.replace()`를 사용하여 기존 데이터 파일을 교체합니다.

이 과정을 통해 저장 도중 문제가 발생했을 때 기존 데이터가 손실될 가능성을 줄였습니다.

### 오류 처리

- `FileNotFoundError`: 데이터 파일이 없는 경우 빈 데이터로 시작
- `JSONDecodeError`: JSON 형식이 잘못된 경우 데이터 손상 안내 후 프로그램 종료
- `PermissionError`: 파일 접근 권한 오류 처리
- `OSError`: 파일 입출력 과정에서 발생하는 오류 처리

### 데이터 복구 방법

`state.json` 파일이 손상된 경우 백업 파일을 이용해 복구할 수 있습니다.

1. 프로그램을 종료합니다.
2. 기존 `state.json` 파일을 별도로 보관합니다.
3. `state.json.bak` 파일을 복사합니다.
4. 복사한 파일의 이름을 `state.json`으로 변경합니다.
5. 프로그램을 다시 실행하여 데이터가 정상적으로 불러와지는지 확인합니다.

백업 파일은 가장 최근 저장 작업 직전의 데이터를 보관합니다.

## 10. Git 및 GitHub 관리

프로젝트의 개발 과정을 기록하고 코드 변경 사항을 관리하기 위해 Git과 GitHub를 사용했습니다.

### Git 사용 목적

- 코드 변경 이력 관리
- 이전 버전으로 복구 가능
- 기능별 개발 과정 기록
- GitHub를 통한 원격 저장소 관리

### 브랜치 전략

기본 개발 브랜치인 `main`을 중심으로 작업하고, 별도의 기능이나 문서 수정이 필요한 경우 작업 브랜치를 생성하여 개발합니다.

작업이 완료되면 변경 사항을 확인한 후 `main` 브랜치에 병합합니다.

예시 명령어:

```bash
# 작업 브랜치 생성 및 이동
git switch -c feature/readme

# 변경 사항 확인
git status

# 변경 사항 저장
git add README.md
git commit -m "Docs: README 설명 보완"

# main 브랜치로 이동
git switch main

# 작업 브랜치 병합
git merge feature/readme
```

### 커밋 메시지 규칙

커밋 메시지는 변경 목적을 쉽게 파악할 수 있도록 유형을 구분하여 작성합니다.

| 유형 | 설명 | 예시 |
|---|---|---|
| `Feat` | 새로운 기능 추가 | `Feat: 퀴즈 검색 기능 추가` |
| `Fix` | 오류 수정 | `Fix: 퀴즈 삭제 오류 수정` |
| `Docs` | 문서 수정 | `Docs: README 설명 보완` |
| `Data` | 데이터 변경 | `Data: 퀴즈 데이터 업데이트` |
| `Refactor` | 코드 구조 개선 | `Refactor: 퀴즈 관리 코드 정리` |

가능한 한 하나의 커밋에는 하나의 기능 또는 변경 목적이 담기도록 작성합니다.

이를 통해 커밋 기록만으로도 어떤 작업이 진행되었는지 쉽게 파악할 수 있습니다.

## 11. 요구사항 변경 시 영향 범위

새로운 요구사항이 추가되거나 기존 기능을 수정할 때 관련 파일과 메서드를 확인하여 변경 범위를 파악합니다.

| 변경 요구사항 | 수정 파일 | 관련 메서드 및 클래스 |
|---|---|---|
| 퀴즈 질문 및 선택지 변경 | `main.py`, `state.json` | `Quiz`, `create_quiz()` |
| 정답 판정 방식 변경 | `main.py` | `Quiz.check_answer()` |
| 퀴즈 삭제 방식 변경 | `main.py`, `state.json` | `delete_quiz()` |
| 점수 계산 방식 변경 | `main.py` | 게임 진행 및 점수 계산 메서드 |
| 최고 점수 관리 방식 변경 | `main.py`, `state.json` | 최고 점수 관리 메서드 |
| 퀴즈 검색 방식 변경 | `main.py` | `search_quiz()` |
| 통계 항목 추가 | `main.py` | `show_statistics()` |
| 데이터 저장 방식 변경 | `main.py` | `load_quizzes()`, `save_quizzes()` |

요구사항에 따라 수정이 필요한 파일과 메서드를 먼저 확인하면 불필요한 코드 수정을 줄이고 기존 기능에 미치는 영향을 파악하기 쉽습니다.
